Who controls what the Nova chatbot knows

This maps how each department sees the bot's documents, how a document gets approved, and what the bot receives while it runs. This is a proposal for a real bank: Nova is fictional. Built today means it exists in the MVP. Proposed needs the bank's agreement.

Who does what at each step

A approves and is accountable. R does the work. C is consulted first. I is told afterwards. Each department approves only the documents it owns. The roles are a proposal, so the bank should map them to its real committees.

What the chatbot receives while running

Always loaded, cached

  • 44 policy rules, each with an ID
  • 24 transaction rules
  • 23 question types and trap rows
  • 50 approved examples
  • Fixed replies, such as fraud

Built today Only approved, live versions should reach this set.

Fetched for each message

  • The masked message and its rewrite
  • This customer's top 5 records
  • Service notices live at that moment
  • The last 3 turns of this chat, masked

Built today Code fetches these. The AI cannot go and look.

Never receives

  • Another customer's data
  • Full card numbers, PIN, OTP or passwords
  • API keys or system secrets
  • Drafts or retired documents
  • Internal legal advice and audit reports
  • Staff-only procedures

The first three are Built today. The rest are Proposed rules for a real document store.

How to pull a wrong document fast

A wrong fee or rule can't wait for a committee. Proposed

Fraud, Compliance or the duty lead can disable one rule at once. The bot then hands that topic to a person, and the owner fixes it through the normal path. Every use of this is logged and reviewed. For anything wider, the kill switch sends every message to a person. Built today
