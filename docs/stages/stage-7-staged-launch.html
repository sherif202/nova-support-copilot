The plan, step by step

  1. Days 1–2Shadow mode on the 200 labelled tickets: node tools/shadow.mjs. Nobody sees the answers. The script compares each route with how an agent closed the ticket and reports how many the copilot would have resolved, the agent minutes saved, answers given where an agent was needed, fraud misses and cost (about US$0.06). Run 30 Oct, 3 times On 200 tickets regenerated from the customer records, each asked at a pinned time, with branch hours and the cheque book price added (1.0.11): would have resolved 63% (126/200; 23% on the unlinked Stage 2 tickets, 59% linked before the new facts), 1,207 agent minutes saved, 0 of 16 fraud missed, intent 100%, priority 100%, 0 answers where an agent was needed, EGP 0.024 per answer, p95 6.0 s (at the gate: watch). Results ›
  2. Days 3–4Internal beta, mode Suggest only: teammates and classmates hold 50 conversations, with fraud and complaint scenarios on purpose. Every AI answer waits for an agent to edit and approve, so a wrong answer never reaches a "customer". Needs testers
  3. Days 5–9Pilot with 10 to 20 people, mode Auto-answer low-risk, each with a scenario card (below). Only the in-scope questions are answered; everything else goes to a person. The PM control panel measures the North Star live. Needs pilot users
  4. OptionalA/B on fee questions: fixed FAQ answers against AI answers. With 20 people the result is a direction, not proof; say so on Demo Day. Optional

Kill-switch rule

Switch the mode to Off at once, until fixed, if:

  • any fraud message is not routed to the Fraud queue (the PM panel raises a HIGH alert);
  • the daily Harmless score drops below 1.00;
  • any full card number appears in the log;
  • the last eval run says DO NOT SHIP.

Tested in build step 13: with the mode Off, a fee question went straight to a person with no AI call, and "3ayez badal fa2ed lel visa" still reached the Fraud queue.
